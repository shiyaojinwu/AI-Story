1. 项目概述
AI-Story 是一款融合 AIGC 技术的综合性平台，前端以 Android 应用为核心载体，采用现代化 Jetpack Compose 技术栈构建，打造出流畅、直观且富有设计感的用户界面。前端不仅提供分镜式故事创作与管理的核心功能，还支持分镜的独立编辑、关键帧图像预览等交互操作，同时为用户配备了风格选择器，满足不同场景下的故事创作需求。作为视频自动化生成平台的交互入口，前端与后端形成高效协同，将复杂的AIGC技术流程封装为简单易用的操作步骤，极大降低了用户的创作门槛，同时其核心后端承担着异构系统编排者（Service Orchestrator）的关键角色，突破传统CRUD业务局限。
针对LLM（大语言模型）与Video Diffusion Model（视频生成模型）在实际应用中面临的高延迟、低并发、不稳定性强等工程挑战，项目后端采用Go语言搭建了异步非阻塞的任务调度架构，成功实现从剧本生成、分镜并行绘制到视频合成的全链路自动化与高可用运行。
平台核心能力涵盖四大关键环节：一是故事结构化解析，可将用户输入的文本故事拆解为结构化的分镜序列；二是图像生成，依据各分镜的文本描述（Prompt）生成对应的关键帧图像；三是语音合成，将分镜旁白文本转换为语音文件；四是视频动态化，把静态关键帧图像转化为动态视频片段，形成完整的AIGC视频创作闭环。

1.1 Jetpack Compose + MVVM
1. Compose 声明式 UI 可以更高效地构建响应式界面，减少传统 View 系统的布局嵌套问题
2. MVVM 模式将业务逻辑与 UI 分离，StoryViewModel.kt 等作为中间层，降低了代码耦合度
3. Compose 与 LiveData/Flow 天然适配，便于实现 UI 状态的自动更新
4. 符合现代 Android 开发最佳实践，社区支持完善
1.2 数据持久化：Room Database
1. Room 是官方推荐的 Android 数据持久化框架，与 SQLite 深度整合
2. 支持类型安全的查询语言，减少 SQL 语法错误
3. 提供 LiveData 支持，数据变化时自动通知 UI
4. 简化数据库版本迁移，在 AppDatabase.kt 中可清晰管理迁移策略
1.3 导航系统：Jetpack Navigation Compose
理由：
1. 实现单 Activity 架构，减少 Activity 切换带来的性能开销
2. 提供类型安全的参数传递，在 AppRoute.kt 中统一管理路由
3. 支持深层链接和导航图可视化编辑，便于团队协作
4. 与 Compose 组件无缝集成，简化导航逻辑

  - 用户价值：让故事创作从抽象文字转变为具象画面，降低创意表达门槛。

  - 核心优势：基于 Jetpack Compose 构建的响应式界面。

  - 设计原因：响应式界面设计可以确保应用在不同设备上都有良好的用户体验。

2. 💡 核心工程亮点 (Engineering Highlights)
2.1 异步任务编排与状态一致性 (Asynchronous Orchestration)
挑战：视频生成模型的推理耗时通常在 30s 到 2min 之间，传统的 HTTP 同步请求极易导致网关超时（Gateway Timeout）或 TCP 连接断开。
解决方案：
- Fire-and-Forget 模式：前端发起任务后，后端仅做校验与初始化，立即返回任务 ID，释放连接资源，将系统的吞吐量与模型推理耗时解耦。
- 最终一致性 (Eventual Consistency)：后端通过轻量级协程（Goroutine）维护长耗时任务，前端通过状态轮询 (Polling) 机制获取 Pending -> Generating -> Completed 的状态流转，保证了用户体验的流畅性。
2.2 基于 Fan-out 模式的高并发吞吐 (Concurrency Pattern)
挑战：一个故事通常包含多个分镜（Shots），串行调用绘图模型会导致总耗时线性增长（O(N)），严重影响生产效率。
解决方案：
- 利用 Go 语言 GMP 模型 的高并发优势，在分镜入库后采用 Fan-out (扇出) 模式。
- 后端瞬间启动 N 个协程并行请求绘图服务，将分镜生成的总耗时降低为 Max(T_model)，最大化利用了底层 GPU 集群的并发能力。
2.3 数据一致性保障 (ACID Transaction)
挑战：业务涉及多步级联操作（LLM 解析 -> 剧本入库 -> 分镜拆解），任何中间环节的失败（如 JSON 解析错误、空数据）都会导致“脏数据”产生（如：故事状态完成，但无分镜）。
解决方案：
- 事务管理：严格使用 GORM Transaction 封装核心链路。确保“分镜数据落地”与“故事状态流转”是一个原子操作。
- 异常熔断：实现完整的错误兜底机制，一旦检测到模型端返回异常（HTML 报错、空切片），立即触发 Rollback 并将状态置为 Failed，保证数据库状态的绝对可信。
2.4 协议解耦与防御性编程 (Decoupling & Defensive Coding)
挑战：底层 Python 模型接口变动频繁，且返回数据格式不可控。
解决方案：
- DTO 隔离：设计专用的 Data Transfer Object (如 VideoGenShot)，将内部数据库实体 (Entity) 与外部接口参数解耦，实现了数据清洗与协议转换。
- 健壮性设计：针对 LLM 可能返回的非 JSON 格式（如 500 HTML 页面），在解析层做了前置校验与日志监控，防止 Panic 导致服务崩溃。
